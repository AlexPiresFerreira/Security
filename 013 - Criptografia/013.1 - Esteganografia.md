## Conceito

**Esteganografia** é a técnica de ocultar a existência de uma informação dentro de outro meio, chamado de **portador**. O portador pode ser uma imagem, áudio, vídeo, texto, documento ou tráfego de rede.

### Esteganografia e criptografia

- **Criptografia:** procura tornar o conteúdo ilegível para quem não possui a chave. A existência dos dados cifrados pode continuar evidente.
- **Esteganografia:** procura ocultar que existe uma mensagem.
- **Combinação:** uma mensagem pode ser cifrada antes de ser ocultada. Isso protege o conteúdo caso a mensagem seja descoberta, mas não garante que a ocultação passe despercebida.

Esteganografia não é sinônimo de **marca d’água digital**. Uma marca d’água normalmente serve para identificar ou rastrear um conteúdo; a esteganografia tem como objetivo principal ocultar informação.

## Tipos de esteganografia

### 1. Imagens

Uma imagem digital pode representar dados em pixels e canais de cor. A técnica **LSB** (*Least Significant Bit*, ou bit menos significativo) altera o último bit de valores dos pixels para codificar dados.

#### Exemplo conceitual

Um canal de cor com valor binário `10110101` tem LSB igual a `1`. Alterá-lo para `10110100` muda o valor numérico de 181 para 180. A diferença pode ser imperceptível em determinadas condições, mas isso depende da imagem, da quantidade de dados inserida e do método usado.

**Limitações importantes:**

- A técnica não é necessariamente invisível a análises estatísticas.
- Redimensionar, editar ou recomprimir a imagem pode corromper os dados.
- JPEG é um formato com perdas; operações de edição e recompressão podem alterar os dados codificados.
- O canal alfa, a paleta de cores e o modo da imagem podem afetar a implementação.
- Um exemplo didático de LSB não deve ser tratado como método seguro de comunicação.

#### Implementação didática em Python

O exemplo abaixo demonstra a ideia em uma imagem **RGB/RGBA não comprimida com perdas**, como PNG. Ele aceita texto UTF‑8, armazena seu tamanho antes da mensagem e verifica a capacidade. Use somente imagens próprias ou de laboratório.

Instale as dependências, se necessário:

```
python -m pip install pillow numpy
```


```
from pathlib import Path

import numpy as np
from PIL import Image


def _carregar_rgb(caminho):
    """Abre uma imagem e retorna uma cópia RGB."""
    with Image.open(caminho) as imagem:
        return imagem.convert("RGB").copy()


def ocultar_texto(entrada, texto, saida):
    imagem = _carregar_rgb(entrada)
    pixels = np.array(imagem, dtype=np.uint8)

    dados = texto.encode("utf-8")

    # Cabeçalho de 4 bytes: tamanho do conteúdo em bytes, ordem big-endian.
    payload = len(dados).to_bytes(4, "big") + dados
    bits = np.unpackbits(np.frombuffer(payload, dtype=np.uint8))

    capacidade_bits = pixels.size
    if len(bits) > capacidade_bits:
        raise ValueError(
            f"Mensagem grande demais: precisa de {len(bits)} bits; "
            f"a imagem comporta {capacidade_bits} bits neste exemplo."
        )

    valores = pixels.reshape(-1)
    valores[:len(bits)] = (valores[:len(bits)] & 0b11111110) | bits

    imagem_modificada = Image.fromarray(pixels, mode="RGB")
    imagem_modificada.save(saida, format="PNG")


def extrair_texto(caminho):
    imagem = _carregar_rgb(caminho)
    valores = np.array(imagem, dtype=np.uint8).reshape(-1)

    # Lê primeiro o cabeçalho de tamanho, com 32 bits.
    bits_cabecalho = valores[:32] & 1
    bytes_cabecalho = np.packbits(bits_cabecalho).tobytes()
    tamanho = int.from_bytes(bytes_cabecalho, "big")

    total_bits = 32 + tamanho * 8
    if total_bits > valores.size:
        raise ValueError("Cabeçalho inválido ou mensagem incompleta.")

    bits_mensagem = valores[32:total_bits] & 1
    dados = np.packbits(bits_mensagem).tobytes()

    return dados.decode("utf-8")


if __name__ == "__main__":
    entrada = Path("original.png")
    saida = Path("stego.png")

    ocultar_texto(entrada, "Mensagem de teste: ação segura.", saida)
    print(extrair_texto(saida))
```


> **Observação:** este código é apenas para demonstração. Não fornece criptografia, autenticação, resistência a esteganálise nem um formato interoperável. O comprimento do texto ocupa 4 bytes; a imagem precisa comportar o cabeçalho e a mensagem.

### 2. Áudio

Técnicas possíveis incluem:

- **LSB:** altera bits de amostras de áudio.
- **Echo hiding:** codifica informação por meio de ecos controlados.
- **Phase coding:** modifica relações de fase em componentes do sinal.

A eficácia e a audibilidade dependem do formato, da técnica e do processamento aplicado. Conversão, normalização, filtragem ou compressão podem destruir a informação oculta.

### 3. Vídeo

Dados podem ser distribuídos entre quadros, amostras de áudio ou estruturas do arquivo. A análise é mais complexa por causa do tamanho do arquivo e da combinação de imagem, áudio e compressão.

### 4. Texto e documentos

Possíveis métodos incluem:

- diferenças de espaçamento, tabulação ou quebras de linha;
- caracteres Unicode visualmente semelhantes;
- metadados e campos opcionais;
- conteúdo inserido em estruturas internas de documentos.

Caracteres visualmente parecidos podem pertencer a alfabetos diferentes. Isso também pode ser usado em ataques de falsificação visual, mas uma ocorrência isolada não comprova intenção maliciosa.

### 5. Arquivos e sistemas de arquivos

Dados podem ser escondidos em metadados, áreas não utilizadas, estruturas anexadas ou recursos específicos do sistema de arquivos.

#### Dados anexados a arquivos

A concatenação de arquivos é uma técnica rudimentar, mas o comportamento depende do formato. Alguns leitores toleram dados adicionais; outros rejeitam o arquivo ou ignoram os dados. Não assuma que um comando como `unzip` localizará automaticamente um arquivo ZIP anexado a qualquer imagem.

#### Slack space

O *slack space* é espaço não utilizado em uma unidade de alocação do sistema de arquivos. Não é simplesmente uma área livre que qualquer aplicação possa usar sem consequências: a existência e o tratamento desse espaço dependem do sistema de arquivos e da forma como os dados foram gravados.

#### Alternate Data Streams (ADS) no NTFS

O NTFS oferece fluxos de dados alternativos associados a arquivos. Eles podem ter usos legítimos, mas também podem ser relevantes numa investigação.

Inspeção defensiva no Windows:


```
dir /r
```

O comando lista fluxos alternativos encontrados nos arquivos do diretório. A presença de um ADS, por si só, não prova atividade maliciosa.

### 6. Rede e canais encobertos

Um **canal encoberto** (*covert channel*) pode transmitir informação de maneira não prevista pelo protocolo ou pela política de segurança. Alguns exemplos conceituais envolvem campos de protocolos, padrões de temporização ou consultas DNS.

Em análise defensiva, procure desvios em relação ao comportamento esperado, como volume ou frequência incomuns, destinos inesperados e uso de protocolos incompatível com a função do dispositivo. Esses sinais precisam ser avaliados junto ao contexto; nenhum deles, isoladamente, confirma um canal encoberto.

## Ferramentas de análise

As ferramentas abaixo ajudam a examinar arquivos. Nenhuma delas detecta todos os métodos, e resultados positivos podem ser falsos positivos.

| Ferramenta | Uso principal |
|---|---|
| `file` | Identificar o tipo provável do arquivo, sem confiar apenas na extensão |
| `exiftool` | Examinar metadados |
| `strings` | Procurar sequências de texto legíveis |
| `binwalk` | Identificar assinaturas e estruturas embutidas em alguns arquivos |
| `zsteg` | Examinar possíveis técnicas LSB em certos arquivos PNG/BMP |
| `steghide` | Trabalhar com dados ocultos em formatos suportados pela ferramenta |
| `StegExpose` | Análise heurística de determinadas formas de LSB em imagens |

**Atenção aos formatos:** `steghide` é associado principalmente a arquivos JPEG e a certos formatos de áudio; não é uma ferramenta genérica para PNG. Confirme os formatos aceitos e as opções na documentação da versão instalada.

### Inspeção inicial

Use arquivos próprios, de laboratório ou cuja análise esteja autorizada. Preserve o original e trabalhe sobre uma cópia.


```
file arquivo
sha256sum arquivo
exiftool arquivo
strings -a arquivo | head
binwalk arquivo
```

Esses comandos são uma triagem inicial; não provam que um arquivo tenha ou não conteúdo oculto.

Para uma análise exploratória de PNG/BMP compatível com `zsteg`:


```
zsteg imagem.png
```

Para `steghide`, consulte primeiro os formatos e parâmetros suportados:


```
bashCopiarsteghide --help
steghide info imagem.jpg
```

Não insira senhas reais em linhas de comando compartilhadas: elas podem ficar no histórico do terminal ou ser visíveis a outros processos. Em investigações, prefira métodos seguros de entrada de credenciais e siga as regras de tratamento de evidências.

## Esteganálise e detecção

**Esteganálise** é o estudo de métodos para identificar ou analisar possíveis dados ocultos.

### Abordagens comuns

#### Análise estrutural

- Verificar se o tipo real corresponde à extensão.
- Procurar dados adicionais ou estruturas inesperadas.
- Comparar tamanho, dimensões e formato com arquivos de referência.
- Examinar metadados e propriedades do arquivo.

#### Análise estatística

Pode procurar padrões ou distribuições atípicas nos dados, inclusive em bits menos significativos. O resultado depende do formato, do algoritmo de ocultação e da imagem de referência.

#### Análise visual e de sinal

Pode revelar distorções em imagens ou áudio, mas técnicas robustas podem não produzir alterações perceptíveis. A ausência de anomalias visíveis não descarta dados ocultos.

#### Análise de tráfego

Em redes, observe padrões incompatíveis com o uso normal do protocolo, volume incomum, consultas repetitivas e destinos fora do padrão operacional. Correlacione os achados com logs de DNS, proxy, firewall e endpoint.

### Limitações

- Um arquivo grande ou metadados incomuns não comprovam esteganografia.
- Um resultado de ferramenta não é confirmação definitiva.
- A compressão e a edição podem remover dados ocultos ou criar artefatos.
- Técnicas desconhecidas podem escapar às ferramentas disponíveis.

## Exemplos defensivos de comandos

### Metadados


```
exiftool -a -G1 arquivo.jpg
```

### Strings legíveis


```
strings -a arquivo.jpg
```

A busca por palavras como `password` ou `secret` pode ajudar em uma triagem, mas não é um detector confiável por si só.

### Assinaturas e arquivos embutidos


```
binwalk arquivo.jpg

```

Uma assinatura identificada precisa ser validada. Ela pode resultar de conteúdo legítimo, de coincidência ou de dados anexados.

### Hash de integridade


```
sha256sum arquivo.jpg
```


Registre o hash antes da análise e, quando necessário, compare-o depois para verificar se o arquivo examinado foi alterado.

## Usos e riscos

### Usos legítimos

- Marca d’água e identificação de conteúdo.
- Pesquisa acadêmica e testes em laboratório.
- Exercícios de CTF e treinamento forense.
- Estudos de detecção e integridade de arquivos.

### Riscos de segurança

- Ocultação de informação em arquivos aparentemente comuns.
- Uso de canais encobertos para dificultar monitoramento.
- Transporte de dados não autorizado ou de componentes maliciosos.

A presença de esteganografia não é, por si só, prova de crime ou de comprometimento. A análise deve considerar a origem do arquivo, o ambiente, a autorização e evidências corroborativas.

## Exemplo de triagem em CTF

> **Cenário fictício:** os nomes de arquivos, offsets e resultados abaixo são ilustrativos. Em um desafio real, os resultados dependem do arquivo fornecido.

1. Preserve o arquivo original e calcule seu hash.
2. Identifique o tipo real e examine metadados.
3. Procure estruturas ou dados adicionais com ferramentas apropriadas.
4. Se houver indício de uma técnica específica, escolha uma ferramenta compatível com o formato.
5. Registre comandos, versões, resultados e limitações.
6. Não execute arquivos extraídos; analise-os em ambiente isolado.

## Contramedidas defensivas

### Para organizações

- Monitorar uploads e fluxos de saída usando contexto, volume e comportamento — não apenas a extensão do arquivo.
- Correlacionar alertas de rede com telemetria de endpoint, proxy, DNS e firewall.
- Aplicar DLP onde houver requisitos claros de proteção e avaliar limitações em arquivos comprimidos ou cifrados.
- Restringir ferramentas e destinos somente conforme a necessidade operacional.
- Definir procedimentos para preservar e analisar arquivos suspeitos.
- Treinar equipes para tratar resultados de ferramentas como indícios, não como prova isolada.

### Para usuários e analistas

- Não confiar apenas no nome ou na extensão do arquivo.
- Não abrir artefatos suspeitos em um equipamento com dados sensíveis.
- Analisar em uma cópia e preservar o original.
- Registrar o hash e o contexto de coleta.
- Evitar enviar arquivos confidenciais para serviços públicos de análise sem autorização.
