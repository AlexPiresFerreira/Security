# 🔍 CWE e CVE — Identificação de Vulnerabilidades

> Sistemas de catalogação de fraquezas e vulnerabilidades mantidos pelo MITRE.
> Ver também: [[Risco-e-Vulnerabilidades]] | [[012.3 - MITRE-ATT&CK]] | [[OWASP-Top-10]]

---

## 📌 Visão Geral

| Sistema | O que é | Foco |
|---------|---------|------|
| **CWE** | Common Weakness Enumeration | Tipo de fraqueza (causa) |
| **CVE** | Common Vulnerabilities and Exposures | Vulnerabilidade específica (instância) |
| **CVSS** | Common Vulnerability Scoring System | Severidade da vulnerabilidade |

> 💡 **Analogia:**
> CWE = "tipo de doença" (ex: diabetes)
> CVE = "caso específico" (ex: paciente X com diabetes)

## 🐛 CWE — Common Weakness Enumeration

### Conceito
Lista categorizada de **tipos de fraquezas** que podem levar a vulnerabilidades.
```

CWE-ID → Nome → Descrição → Exemplos → Mitigação

```

### CWEs Mais Importantes para CEH

#### CWE-79 — Cross-Site Scripting (XSS)


phpCopiar# Vulnerável
<div>Bem-vindo, <?php echo $_GET['nome']; ?></div>

# Ataque
?nome=<script>alert(document.cookie)</script>



**Mitigação:**
- Output encoding
- Content Security Policy (CSP)
- Input validation

---

#### CWE-89 — SQL Injection


phpCopiar# Vulnerável
$query = "SELECT * FROM users WHERE user='" . $_POST['user'] . "'";

# Ataque
' OR '1'='1' --



**Mitigação:**
- Prepared Statements
- ORM
- Input validation

> Ver detalhes → [[OWASP-Top-10]]

---

#### CWE-22 — Path Traversal


phpCopiar# Vulnerável
$file = $_GET['arquivo'];
include("/var/www/uploads/" . $file);

# Ataque
?arquivo=../../../../etc/passwd



**Mitigação:**
- Validação de paths
- Whitelist de arquivos
- Chroot/jail

---

#### CWE-798 — Hard-Coded Credentials


pythonCopiar# Vulnerável ❌
DB_PASSWORD = "admin123"

# Correto ✅
DB_PASSWORD = os.environ.get("DB_PASSWORD")



**Mitigação:**
- Variáveis de ambiente
- Vaults (HashiCorp, AWS Secrets Manager)

---

#### CWE-502 — Deserialization of Untrusted Data


pythonCopiar# Vulnerável ❌
import pickle
data = pickle.loads(user_input)

# Correto ✅
import json
data = json.loads(user_input)

## 🚨 CVE — Common Vulnerabilities and Exposures

### Conceito
Identificador único para **vulnerabilidades específicas** descobertas em software/hardware.

### Formato do ID
```

CVE-YYYY-NNNNN

CVE → Prefixo fixo YYYY → Ano de atribuição NNNNN→ Número sequencial (4-7 dígitos)

```
### Anatomia de um CVE
```

CVE-ID: CVE-2021-44228 Nome: Log4Shell Descrição: RCE via JNDI lookup no Apache Log4j CVSS Score: 10.0 (CRÍTICO) Data: 2021-12-10 Afetados: Log4j 2.0-beta9 até 2.14.1 CWE Relacionado: CWE-502 (Deserialization) Patch: Atualizar para 2.17.1+

```

## 📊 CVSS — Common Vulnerability Scoring System

### Escala de Severidade

| Score | Severidade | Ação |
|-------|-----------|------|
| 0.0 | None | ⚪ Nenhuma |
| 0.1 – 3.9 | Low | 🟢 Monitorar |
| 4.0 – 6.9 | Medium | 🟡 Planejar patch |
| 7.0 – 8.9 | High | 🟠 Patch urgente |
| 9.0 – 10.0 | Critical | 🔴 Patch imediato |

### Componentes do CVSS v3.1

| Componente | Sigla | Opções |
|------------|-------|--------|
| Attack Vector | AV | Network (N), Adjacent (A), Local (L), Physical (P) |
| Attack Complexity | AC | Low (L), High (H) |
| Privileges Required | PR | None (N), Low (L), High (H) |
| User Interaction | UI | None (N), Required (R) |
| Scope | S | Unchanged (U), Changed (C) |
| Confidentiality | C | None (N), Low (L), High (H) |
| Integrity | I | None (N), Low (L), High (H) |
| Availability | A | None (N), Low (L), High (H) |

### Exemplo — Log4Shell
```

CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:H

AV:N → Rede (remoto) AC:L → Baixa complexidade PR:N → Sem privilégios UI:N → Sem interação do usuário S:C → Afeta outros componentes C:H → Confidencialidade: alto impacto I:H → Integridade: alto impacto A:H → Disponibilidade: alto impacto

Score: 10.0 ← CRÍTICO MÁXIMO

```
> Calculadora: [nvd.nist.gov/vuln-metrics/cvss/v3-calculator](https://nvd.nist.gov/vuln-metrics/cvss/v3-calculator)

## 📋 Workflow de Gestão de Vulnerabilidades
```

1. IDENTIFICAR → Nmap, Nuclei, Nessus, OpenVAS
    
2. PRIORIZAR → CVSS Score + Exploitabilidade + Impacto no negócio → Crítico + Exploit público = URGENTE
    
3. REMEDIAR → Patch oficial → Workaround temporário (WAF, IPS, segmentação)
    
4. VERIFICAR → Re-scan após patch → Confirmar versão atualizada
    
5. DOCUMENTAR → Registrar no vulnerability register → Atualizar risk register → [[Risco-e-Vulnerabilidades]]
    

```
