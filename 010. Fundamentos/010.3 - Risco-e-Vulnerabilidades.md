# ⚠️ Risco e Vulnerabilidades

> Conceitos fundamentais de gestão de risco em segurança da informação.
> Ver também: [[CIA-Triad]] | [[CWE-CVE]] | [[Defesa-em-Profundidade]] | [[012.4 - NIST-Cybersecurity-Framework(CSF)]]

---

## 📌 Conceitos Fundamentais

### 🎯 Ativo (Asset)
Qualquer coisa de **valor** para a organização.

| Tipo | Exemplos |
|------|---------|
| 💾 Dados | Informações de clientes, propriedade intelectual |
| 💻 Hardware | Servidores, laptops, switches |
| 📱 Software | Aplicações, sistemas operacionais |
| 👥 Pessoas | Funcionários, conhecimento |
| 🏢 Instalações | Data centers, escritórios |
| 🔑 Reputação | Marca, confiança do cliente |

---

### 🐛 Vulnerabilidade (Vulnerability)
**Fraqueza** ou **falha** que pode ser explorada.

| Tipo | Exemplos |
|------|---------|
| 🔧 Técnica | Software desatualizado, buffer overflow, SQLi |
| 👥 Humana | Engenharia social, negligência, insider threat |
| 🏢 Física | Falta de controle de acesso, sem CCTV |
| 🔄 Processual | Falta de políticas, ausência de auditoria |

> Para CVEs e CWEs específicos → [[CWE-CVE]]

---

### 🎭 Ameaça (Threat)
**Potencial** causa de incidente que pode causar dano.

| Tipo | Exemplos |
|------|---------|
| 🌐 Cibernética | Malware, Ransomware, Phishing, DDoS, APTs |
| 🌍 Natural | Terremotos, enchentes, incêndios |
| 👥 Humana | Erro humano, sabotagem, espionagem |
| 🔧 Técnica | Falha de hardware, queda de energia |

---

### 💥 Risco (Risk)
**Probabilidade** de ameaça explorar vulnerabilidade e causar impacto.
```

Risco = Ameaça × Vulnerabilidade × Impacto

```
**Simplificado:**
```

Risco = Probabilidade × Impacto

```
**Exemplo:**
```

Ameaça: Ransomware Vulnerabilidade: Servidor Windows desatualizado Impacto: Perda de dados + parada de operação Resultado: Risco = ALTO

```
---

### 💔 Impacto (Impact)
**Consequência** negativa se o risco se materializar.

| Dimensão | Exemplos |
|----------|---------|
| 💰 Financeiro | Perda de receita, multas, custos de recuperação |
| 🏢 Operacional | Parada de serviços, perda de produtividade |
| 🎭 Reputacional | Perda de confiança, dano à marca |
| ⚖️ Legal | Multas LGPD/GDPR, processos judiciais |

## 📊 Gestão de Riscos

### Processo em 5 Etapas
```

1. Identificação
2. Análise
3. Avaliação
4. Tratamento
5. Monitoramento

```
---

### 1️⃣ Identificação de Riscos

**Métodos:**
- Brainstorming
- Entrevistas
- Análise de histórico de incidentes
- Threat modeling

**Exemplo de Risk Register:**

| ID | Risco | Ameaça | Vulnerabilidade | Prob | Impacto |
|----|-------|--------|-----------------|------|---------|
| R1 | Ransomware | Malware | Patches atrasados | Alta | Alto |
| R2 | Phishing | Email malicioso | Falta de treino | Média | Médio |

---

### 2️⃣ Análise de Riscos

#### Qualitativa (Subjetiva)

**Probabilidade:**

| Nível | Faixa |
|-------|-------|
| Muito Baixa | < 10% |
| Baixa | 10–30% |
| Média | 30–50% |
| Alta | 50–70% |
| Muito Alta | > 70% |

**Impacto:**

| Nível | Valor |
|-------|-------|
| Muito Baixo | < R$ 10k |
| Baixo | R$ 10k–50k |
| Médio | R$ 50k–200k |
| Alto | R$ 200k–1M |
| Muito Alto | > R$ 1M |

---

#### Quantitativa (Numérica)

##### ALE — Annual Loss Expectancy
```

ALE = SLE × ARO

SLE (Single Loss Expectancy) = Perda por incidente ARO (Annual Rate of Occurrence) = Frequência anual

```
**Exemplo:**
```

Ativo: Servidor de banco de dados SLE: R$ 200.000 ARO: 0,3 (30% ao ano)

ALE = R$ 200.000 × 0,3 = R$ 60.000/ano

```
> 💡 **Dica CEH:** ALE, SLE e ARO são muito cobrados!
> Memorize a fórmula: **ALE = SLE × ARO**

---

### 3️⃣ Avaliação de Riscos

#### Matriz de Risco
```

```
             IMPACTO
         Baixo  Médio  Alto
    ┌───────┬───────┬──────┐
```

Alta │ 🟡 │ 🟠 │ 🔴 │ ├───────┼───────┼──────┤ Média │ 🟢 │ 🟡 │ 🟠 │ ├───────┼───────┼──────┤ Baixa │ 🟢 │ 🟢 │ 🟡 │ └───────┴───────┴──────┘

🟢 Baixo: Aceitar 🟡 Médio: Monitorar 🟠 Alto: Mitigar 🔴 Crítico: Mitigar urgentemente

```
---

### 4️⃣ Tratamento de Riscos

| Opção | O que faz | Exemplo |
|-------|-----------|---------|
| 🛡️ Mitigar | Reduz probabilidade/impacto | Instalar EDR, aplicar patches |
| 🔄 Transferir | Passa o risco para terceiros | Contratar seguro cibernético |
| ✅ Aceitar | Aceita quando custo > impacto | Blog pessoal × CDN |
| 🚫 Evitar | Elimina a atividade geradora | Não usar cloud pública |

#### ROI de Controle (Mitigação)
```

Se ALE = R$ 60.000/ano E controle custa R$ 20.000/ano E reduz risco em 80%:

Benefício = R$ 60.000 × 0,8 = R$ 48.000 Custo = R$ 20.000 ROI = R$ 48.000 - R$ 20.000 = R$ 28.000 ✅

```
---

### 5️⃣ Monitoramento e Revisão

**KRIs (Key Risk Indicators) — Exemplos:**
- Número de tentativas de phishing/mês
- Tempo médio para aplicar patches críticos
- Número de vulnerabilidades críticas abertas
- Uptime de sistemas críticos

## 🎯 Frameworks de Gestão de Riscos

| Framework | Foco | Uso |
|-----------|------|-----|
| ISO 31000 | Princípios gerais | Qualquer organização |
| NIST RMF | Segurança de TI | Governo + corporativo |
| FAIR | Análise quantitativa | Risco cibernético |
| ISO 27005 | Risco em segurança da informação | ISO 27001 |

### NIST RMF — 6 Etapas
```

1. Categorize → Classificar sistemas
2. Select → Selecionar controles
3. Implement → Implementar controles
4. Assess → Avaliar eficácia
5. Authorize → Autorizar operação
6. Monitor → Monitorar continuamente

```
> Ver detalhes → [[012.4 - NIST-Cybersecurity-Framework(CSF)]]

## 📋 Exemplo Prático — E-commerce
```

Ativo: Sistema de pagamento (R$ 5M/ano) Ameaça: SQL Injection Vulnerabilidade: App sem input validation

SLE: R$ 750.000 (parada + multa LGPD + reputação) ARO: 0,4 (40% de chance ao ano) ALE: R$ 300.000/ano

Opção 1 - Mitigar: Pentesting: R$ 30.000 WAF: R$ 50.000/ano Refatoração: R$ 100.000 Total: R$ 180.000 Redução: 90% Novo ALE: R$ 30.000 ROI: R$ 90.000 ✅

Decisão: Mitigar — Melhor ROI!

```
