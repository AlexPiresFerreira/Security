# 🔐 IAAA — Identificação, Autenticação, Autorização e Auditoria

> Conjunto de processos que garantem segurança no acesso a sistemas.
> Ver também: [[CIA-Triad]] | [[Defesa-em-Profundidade]] | [[Analise-de-Logs]]

---

## 📌 Conceito

**IAAA** são quatro etapas que trabalham juntas para proteger
recursos e sistemas. Funcionam em sequência:
```

Identificação → Autenticação → Autorização → Auditoria

```
---

## 1️⃣ Identificação

### Definição
Processo de **declarar quem você é** no sistema.

### Exemplos
| Tipo | Exemplo |
|------|---------|
| Nome de usuário | joao.silva |
| E-mail | joao@empresa.com |
| CPF | 123.456.789-00 |
| ID de funcionário | EMP-0042 |

> ⚠️ Identificação apenas **declara** — não prova nada!
> A prova vem na próxima etapa.

---

## 2️⃣ Autenticação

### Definição
Processo de **provar que você é quem diz ser**.

### Fatores de Autenticação

| Fator | Nome | Exemplos |
|-------|------|---------|
| 🧠 | Algo que você **SABE** | Senha, PIN, resposta secreta |
| 📱 | Algo que você **TEM** | Token, smartphone, cartão |
| 👤 | Algo que você **É** | Biometria, voz, íris |

### MFA (Multi-Factor Authentication)
> Combinação de **dois ou mais fatores** distintos.

**Exemplo:**
```

Fator 1: Senha (algo que sei) Fator 2: Token SMS (algo que tenho) = MFA ativo ✅

```
> 💡 **Dica CEH:** 2FA é um tipo de MFA — usa exatamente 2 fatores.
> MFA pode usar 3 ou mais.

---

## 3️⃣ Autorização

### Definição
Processo de **definir o que você pode fazer** após autenticação.

### Modelos de Controle de Acesso

| Modelo | Sigla | Como funciona |
|--------|-------|--------------|
| Access Control List | ACL | Lista de permissões por recurso |
| Role-Based Access Control | RBAC | Permissões baseadas em função/cargo |
| Attribute-Based Access Control | ABAC | Permissões baseadas em atributos |
| Mandatory Access Control | MAC | Classificação de segurança obrigatória |
| Discretionary Access Control | DAC | Dono do recurso define permissões |

### Princípio do Menor Privilégio
> Usuário tem apenas os acessos **mínimos necessários**
> para realizar seu trabalho.

**Exemplo RBAC:**
```

Usuário: João Silva Função: Analista de Suporte

Permissões: ✅ Ler tickets ✅ Responder tickets ❌ Deletar tickets ❌ Acessar configurações do sistema

```
---

## 4️⃣ Auditoria

### Definição
Processo de **registrar e monitorar** todas as ações no sistema.

### Princípio: "No Logs, No Crime"
> Sem logs não há investigação possível!

### As 5 Perguntas do Log

| Pergunta | Inglês | O que registrar |
|----------|--------|----------------|
| Quem? | Who | Usuário que agiu |
| O quê? | What | Ação realizada |
| Quando? | When | Data e hora exata |
| Onde? | Where | Sistema/recurso acessado |
| Por quê? | Why | Contexto (quando aplicável) |

### Exemplo de Log
```

[2026-10-20 10:45:23] USER: joao.silva ACTION: DELETE RESOURCE: /config/firewall.conf STATUS: DENIED IP: 192.168.1.50

```
### Ferramentas de Auditoria

| Ferramenta | Tipo | Uso |
|------------|------|-----|
| Splunk | SIEM | Correlação de eventos |
| Wazuh | SIEM open source | Monitoramento |
| ELK Stack | SIEM open source | Análise de logs |
| Windows Event Viewer | OS | Logs Windows |
| Syslog | OS | Logs Linux/Unix |

> Ver também: [[Analise-de-Logs]] | [[SIEM-Conceitos]]

## 💡 Dicas CEH

> **Questão clássica:**
> "Qual etapa do IAAA define O QUE o usuário pode fazer?"
> → **Autorização** ✅

> **Questão clássica:**
> "Qual etapa PROVA a identidade do usuário?"
> → **Autenticação** ✅

> **Questão clássica:**
> "Qual fator de autenticação é uma impressão digital?"
> → **Algo que você É** (biometria) ✅

| Confusão comum | Correto |
|----------------|---------|
| Identificação = prova | ❌ Só declara |
| Autenticação = permissão | ❌ Só prova |
| Autorização = log | ❌ Define acesso |
